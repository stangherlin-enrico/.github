## Engineering Principles

<table>
<tr>
<td width="36" align="center">🎯</td>
<td><strong>Simplicity over cleverness</strong> — the best code is the code nobody needs to explain</td>
</tr>
<tr>
<td align="center">🔍</td>
<td><strong>Explicitness over magic</strong> — behaviour should be readable, not inferred</td>
</tr>
<tr>
<td align="center">🧪</td>
<td><strong>Testability over convenience</strong> — if it's hard to test, the design is wrong</td>
</tr>
<tr>
<td align="center">📝</td>
<td><strong>Documentation is part of the product</strong> — undocumented software is incomplete software</td>
</tr>
<tr>
<td align="center">♿</td>
<td><strong>Accessibility is not optional</strong> — inclusive by design, not as an afterthought</td>
</tr>
<tr>
<td align="center">🏗️</td>
<td><strong>Architecture exists to reduce future cost</strong> — good structure pays compound interest</td>
</tr>
<tr>
<td align="center">🌱</td>
<td><strong>Software should age gracefully</strong> — write for the next developer, not just the next deadline</td>
</tr>
</table>

## Open Source Philosophy

I publish software I would personally trust in production.

- **Minimal external dependencies** — every dependency is a liability
- **High test coverage** — confidence, not ceremony  
- **Stable, versioned APIs** — breaking changes have a cost
- **Long-term maintainability** — write for the next developer
- **Clear documentation** — part of the product, not an afterthought
- **Predictable behaviour** — no surprises in production
